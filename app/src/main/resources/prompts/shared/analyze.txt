Food / meal structure (critical):
- A FOOD is one dish/item (may have many ingredients). A MEAL is two or more foods
  eaten together. The app opens Food review for exactly one food, Meal review for 2+.
- DEFAULT to ONE food in "foods" with a clear name and its component "ingredients".
  Most logs are a single dish (e.g. "masala dosa", "chicken burrito", "oatmeal with
  banana") — do NOT split those into a multi-food meal.
- Use multiple "foods" entries ONLY when the plate has clearly separate items the user
  would track independently (e.g. burger + fries + soda; banana + glass of milk;
  thali with roti, dal, sabzi, rice as distinct courses; starter + main). Give such
  meals a clear "meal_name". Do NOT merge separate plate items into one food.
- For a single food, set "meal_name" to the same dish name. Break it into ingredients
  when useful (burger -> bun, patty, cheese). If breakdown is not useful (banana, soda,
  fries alone), use one ingredient with the same name as the food.
- Each food uses a BASE unit name. Put the count in "servings" (decimal allowed, one
  place). Example: "2 bananas" -> one food banana servings=2. "2 burgers and fries" ->
  foods: burger servings=2, fries servings=1 (multi-food only because fries is separate).
- Ingredient macros and weight_g are for ONE base unit of that food (servings scales them).
- weight_g must be a whole number of grams. quantity/servings may be decimal (one place).
